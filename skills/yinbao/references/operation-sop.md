# 银豹高效操作 SOP

目标：在门店范围、数据口径和写入结果可验证的前提下，减少页面跳转、重复登录、重复读取与无效重试。

## 1. 开始前只确定五项

1. 账号：ERIN000、ERIN001 或 ERIN002。
2. 门店：具体门店或全部门店。
3. 动作：只读查询、测试写入或正式写入。
4. 对象：会员号、商品条码、流水号或员工工号。
5. 时间：明确起止时间和统计口径。

ERIN001 默认只读；ERIN002 可测试写入；总部、共享、复制、调货和真实支付不按普通测试处理。已有信息不重复向用户询问。

## 2. 登录和页面连接

1. 优先复用已登录会话，并保持浏览器在后台。
2. 先读取一次当前标签页、网址和登录状态。用户已说明登录成功时，直接进入业务页面，不再停留或重试登录。
3. 已知功能路径时直接打开目标网址，不从首页逐层展开菜单。
4. 连接预检最多 30 秒；失败先读取状态，连续两次失败改用已验证通道。2026-10-02 已验证独立 headless Playwright CLI，页面读取中位约 0.665 秒、P95 约 1.761 秒，不含 CLI 启动、登录和完整业务操作。不要沿用历史约一分钟的逐页等待。
5. 一个任务尽量复用同一标签页，任务未结束时保留会话，避免下一轮再次登录。

## 3. 写入操作

2026-10-02 补充：ERIN002 门店账号的门店选择器可能隐藏，不点击隐藏控件。先验证 `#hf_storeId=4402560`；存在表单门店字段时还要核实其目标。会员等级由总部统一设置，即使登录测试店也不能按店内测试修改。系统设置部分开关点击即保存；与新增表单的“保存”区分。相关验证见 `skills/yinbao/references/test-results.md`。

1. 提交前核对页面标题、所属门店和表单中的门店字段均为 `002 - erin002`。
2. 测试对象统一使用 `【测试勿售】` 或 `CODEXTEST`，事先一次确定名称、分类、条码和价格。
3. 同类基础资料按依赖顺序建立：分类 → 产品/服务 → 次卡 → 会员 → 销售。
4. 一次填完必填字段后提交一次。系统响应慢或超时时，先回读列表或详情确认是否成功，禁止重复提交。
5. 保存后立即记录对象标识和最终状态；销售后立即记录流水号、会员、支付方式和金额。

## 4. 收银端测试

1. 先看顶部账号、门店和收银员工号；确认是 ERIN002 后再操作。
2. 每张测试单只验证一个核心动作，减少多个功能混在一张单中造成口径不清。
3. 挂会员、选择商品/服务/卡项、选择导购、结算前各检查一次；结算后记录流水号。
4. 若用户已经完成收银操作，直接从后台“销售单据”读取实际结果，不重复操作收银端。
5. 若后台发现未挂会员、未挂导购或支付方式错误，先报告实际状态；不擅自补单、反结账或退款。

## 5. 后台回读的最短路径

先查原始单据，再根据问题定向查明细和汇总。原始单据是金额、会员和流水号的首要依据。

| 要回答的问题 | 首选入口 | 必要时追加 |
|---|---|---|
| 一张交易发生了什么 | 销售 → 销售单据 | 库存变动、绩效明细 |
| 会员买了什么、消费多少 | 会员资料 → 详细 | 会员消费汇总 |
| 产品/服务/卡项销量 | 商品销售统计 | 分类销售统计 |
| 产品库存是否扣减 | 库存 → 变动明细 | 销售单据 |
| 次卡购买、核销和剩余 | 次卡概况 | 次卡购买明细、次卡使用明细、会员持卡明细 |
| 收银员或导购业绩 | 收银员业绩、绩效明细 | 技师导购绩效、实收与消耗绩效 |
| 门店收了多少钱 | 门店支付汇总 | 销售单据、营业概况 |

查询顺序固定为：门店 → 时间 → 精确标识 → 查询 → 回读筛选状态 → 记录结果。能够用流水号、会员号或测试条码精确筛选时，不做无目的分页。

已验证的直接路径可拼接在后台域名后使用：

| 功能 | 路径 |
|---|---|
| 销售单据 | `/Report/Tickets` |
| 会员消费汇总 | `/CustomerReport/CustomerConsumerSummary` |
| 商品销售统计 | `/ReportV2/ProductSale` |
| 次卡概况 | `/PassProduct/CustomerPassProductSummary` |
| 次卡购买明细 | `/PassProduct/CustomerPassProduct` |
| 次卡使用明细 | `/PassProduct/CustomerPassProductUsageLog` |
| 会员持卡明细 | `/PassProduct/CustomerOwnPassProduct` |
| 库存变动明细 | `/Inventory/StockChangeHistory` |
| 收银员业绩 | `/Cashier/CashHistory` |
| 技师导购绩效 | `/Guider/GuiderCommissionCount` |
| 绩效明细 | `/Guider/GuideHistory` |
| 员工实收业绩 | `/Guider/GuiderPerformanceStatistics` |
| 实收与消耗绩效 | `/Guider/CountGuiderCashCardAmount` |
| 门店支付汇总 | `/ReportV2/StorePaymentSummary` |
| 分类销售统计 | `/Custom/CategorySale` |

## 6. 数据口径

- 销售单据：逐单事实来源。
- 会员消费汇总：只含已关联该会员的交易。
- 商品销售统计：次卡核销会增加服务销量。
- 门店支付汇总：区分营业实收、总金额、现金和次卡支付。
- 收银员业绩：可能把次卡核销金额计入“实收”，不等同于现金实收。
- 技师/导购报表：只统计已归属员工的行；不同绩效页的实收、劳动和消耗口径不同。

遇到数字不一致时，只追加检查能解释差异的页面，不遍历所有报表。按会员是否关联、导购是否关联、支付方式、现金与卡消耗、单据是否有效的顺序排查。

## 7. 工具和用量控制

- 一个事实优先读取一个权威页面；只有出现矛盾或金额风险时才做第二来源交叉验证。
- 一次页面访问同时提取标题、筛选范围、目标行和合计，不拆成多次读取。
- DOM/可访问文本足够时不截屏；不为“熟悉系统”重复打开已记录页面。
- 已有路径查 `功能目录.tsv` 和本 SOP；不重新遍历 191 个菜单。
- 开放接口仅在具备对应门店凭据且比后台更省调用时使用。采用精确条件和最大合理页容量，避免试探请求；默认免费额度为 300 次/天。
- 连续失败两次即停止相同做法，读取状态并更换路径；不进行无限重试。

## 8. 完成标准与输出

每项结果必须包含：门店、时间范围、对象标识、数据值、统计口径、获取时间和验证程度。写入任务还需包含提交结果及回读结果。

输出先给结论，再列异常和影响；只报告与用户目标有关的数据。未验证的入口标为“候选”或“页面已读取”，不能写成“已完成”。
