# 已知数据口径及校验

先定义时间字段（销售时间/核销时间/开卡时间/充值时间）和门店字段（销售店/开卡店/购买店/消费店）。同名金额字段不能直接合并。

|问题|首选事实来源|差异检查|
|---|---|---|
|销售、退款、作废|销售单据及商品/支付明细|有效标志、退款方向、多支付方式、抹零、赠送|
|门店实收|门店支付汇总，必要时原始单据|储值充值与消费、次卡购买与核销、卡支付与现金|
|会员消费|会员关联的销售单据/会员消费汇总|散客单未关联会员不计入；退款及跨店归属|
|剩余项目|会员持卡明细，并按项目/卡实例下钻|有效期有效不等于剩余次数大于零；过期未用单列；无限次不可转成普通次数|
|员工绩效|绩效明细、技师导购绩效、实收与消耗绩效|收银员与导购不是同一角色；未归属导购的销售不计入导购；多人分配、提成方案|
|库存|库存变动明细，关联商品条码和销售/货流单|商品、服务、卡项分开；寄存取、报损、盘点和核销耗材不是相同动作|

已验证的 ERIN002 历史案例（2026-09-07，不是当前数值）：门店支付汇总现金 6.00、次卡核销 3.00、总金额 9.00；会员汇总只关联三笔，合计 7.00；额外无会员项目单不计入会员汇总。商品现金单未挂导购，不出现在技师明细。收银员页的“实收”可能含卡核销，不能当成现金到账。

剩余项目导出流程：购买门店选择目标店 → 卡类型分别取全部/有效/过期 → 导出 → 检查门店列和行数 → 按卡实例、会员、项目汇总。只统计剩余大于零的有限次项目；无限次独立计数。分析项目集中度、会员集中度、过期/临期、长期未到店。剩余价值是待履约指标，不直接等于可退金额或会计负债。

读取 xlsx 时先核对工作表、表头、总行数、导出时间、文件更新时间和筛选范围；旧导出只能作历史快照。大整数 ID 按字符串；金额用十进制/分单位；保留原始来源，不通过名称合并重名会员/商品。

开放 API 默认额度 300 次/天；门店业务数据需要对应门店 appId/appKey。总部凭据仅验证过列店，不能猜测或混用门店密钥。后台浏览器请求与开放 API 分开记录，但都采用精确条件，避免无目的抓取。
